# Step 4: Draft the post

Only when `--post` was passed. A teardown makes good post material for one
reason: it is not an announcement. Nobody owes you attention for shipping
something. People will read a specific, checkable claim about a thing they have
already seen on their timeline.

## What the post is

One surprising number, one honest verdict, one thing the reader can use.

```
Hook       : the number or the gap. Not the repo name.
Mechanic   : what it actually does, two sentences.
The catch  : claims vs code, or what it delegates to, or the real weight.
Verdict    : ADOPT / STEAL / SKIP and why, in your own voice.
Takeaway   : the one thing worth stealing regardless.
```

## Rules

**Every number traces to step 1.** Line counts, ratios, file counts, dependency
counts, all from the measurement output. Never compute a number in prose, and
never round a number into a vibe ("thousands of lines" when you have the count).

**Name the repo and link it.** A teardown that hides its subject is a subtweet.

**No dunking.** The verdict can be SKIP; the tone stays level. Someone built
this. The post is about the mechanic, not the person. A SKIP that reads as
contempt is a worse post and a worse signal about you.

**Credit what is good.** Almost every SKIP has one thing worth taking. Lead the
takeaway with it.

**No launch language.** "Excited to share", "game-changer", "under the hood",
"deep dive". Cut them. If the post would survive as a plain sentence spoken out
loud, it survives.

**One post per repo per day, maximum.** A feed of teardowns reads as a grudge.
A steady one-a-day reads as a practice.

## The honest-negative rule

If the teardown found nothing, and the repo is fine, ordinary and already
duplicated by three others, that is not a post. Do not manufacture a contrarian
angle to have something to publish. The absence of a post is a valid output of
this step, and a feed that only posts when there is something real is the whole
asset.
